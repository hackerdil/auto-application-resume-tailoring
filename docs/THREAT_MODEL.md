# Threat Model

Scope: Career Agent MVP running locally for one owner (see [ARCHITECTURE.md](ARCHITECTURE.md)). Method: assets → actors → trust boundaries → abuse cases with mitigations → residual risks. Each mitigation names the enforcing component and the test category that proves it. Update this file whenever a boundary changes.

## 1. Assets

| ID  | Asset                                                                          | Sensitivity                                        |
| --- | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| A1  | Verified fact bank, profile, résumé originals                                  | High (PII)                                         |
| A2  | Sensitive saved answers: authorization, salary, demographics, criminal history | Very high                                          |
| A3  | Browser profile: ATS session cookies                                           | Very high (account takeover)                       |
| A4  | Provider credentials: `OPENAI_API_KEY`, Claude Code session                    | High (cost, account)                               |
| A5  | `DATA_ENCRYPTION_KEY`, `LOCAL_SESSION_SECRET`                                  | Critical                                           |
| A6  | Approval tokens                                                                | High (authorizes an external, irreversible action) |
| A7  | Integrity of submitted applications (truthfulness, right job, right files)     | High (reputation, legal)                           |
| A8  | Audit log                                                                      | Medium (integrity matters more than secrecy)       |
| A9  | Cost budget / plan limits                                                      | Medium                                             |

## 2. Actors

- **Owner** — trusted, but can make mistakes (approve too fast).
- **Hostile web content** — job descriptions, ATS pages, iframes, redirects: untrusted, may contain prompt injection.
- **Hostile documents** — imported résumés/attachments: untrusted (malformed PDFs, zip bombs, embedded instructions).
- **LLM providers** — honest-but-fallible: may hallucinate, follow injected instructions, or emit invalid output.
- **Other local processes / malicious websites in the owner's everyday browser** — may try to reach `127.0.0.1` ports (CSRF, DNS rebinding).
- **Supply chain** — npm dependencies, Playwright browser builds.
- **Repository contributors / coding agents** — may accidentally commit secrets or weaken controls.

## 3. Trust boundaries

| ID  | Boundary                                                       |
| --- | -------------------------------------------------------------- |
| TB1 | Owner's browser ⇄ local API (HTTP on loopback)                 |
| TB2 | Worker ⇄ external job-source APIs (HTTP egress)                |
| TB3 | Worker ⇄ LLM providers (data leaves the machine)               |
| TB4 | Model output ⇄ tool execution (model proposes, code disposes)  |
| TB5 | Automated browser ⇄ third-party ATS pages                      |
| TB6 | Imported files ⇄ parsers                                       |
| TB7 | Application ⇄ disk (DB, artifacts, profile, logs)              |
| TB8 | Claude Code (development agent) ⇄ repository and local secrets |

## 5. Residual risks

1. **Owner rubber-stamping.** The review screen can be approved without reading. Mitigated only by UX (one application per approval, short TTL, explicit data listing).
2. **Heuristic classification gaps.** A novel consent/sensitive field phrasing could be misclassified. Unknown fields default to `requires_user`, but a confidently mislabelled field remains possible.
3. **Confirmation predicates.** ATS success pages change; a false-positive predicate could mark `SUBMITTED` incorrectly. Predicates are adapter-specific and conservative; mismatch yields `SUBMISSION_UNCERTAIN`.
4. **Local machine compromise.** Malware with the owner's privileges can read the keychain, browser profile and DB. Out of scope.
5. **Provider data handling.** Résumé facts and job text are sent to OpenAI/Anthropic under their terms. Disclosed in onboarding; `dry-run` and `research-only` reduce exposure.
6. **Subagent concurrency cap** is advisory only (ADR-014).
7. **LLM reviewer agreement is not proof.** The deterministic validator is the hard gate; model review only adds findings.
